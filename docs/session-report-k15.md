## 1. Понимание задачи и границы

Цель, как она была в первом сообщении сессии (2026-11-25T12:32:00Z): во входящих
сообщениях `contract-service` необязательные текстовые, GUID- и датовые поля
больше не считать пустыми, если в JSON пришёл не строковый узел. Такой узел —
нарушение контракта. Пусто только при отсутствии ключа или JSON `null`.

В область вошли три входящих потока, которые уже читают эти поля через
`OptionalField`:

- задача на выпуск, ДГ-01 (`ContractTaskUpserted`): `program_id`, поля
  персональных данных (`middle_name`, `address`, серия, кем и когда выдан,
  код подразделения), `relation_type`;
- прекращение, ДГ-02 (`ContractTaskCancelled`): `cancel_comment`;
- выпуск полиса ЛМ, ДГ-07 (`LmPolicyIssued`): `policy_usk_number`.

Код правки один: `OptionalField.text`, `uuid`, `date`. Рядом — unit-тесты
парсеров, новая фича и новые step-классы, абзацы `design.md`, `operations.md`
и `CHANGELOG.md`. Diff против базы на момент PR — те же 15 файлов
`contract-service`. `gauntlet/` сессия не редактировала: туда попадали только
merge с `origin/main`.

Вне фичи оставлено сознательно, частью по вопросам владельцу:

- событие оплаты Ordering (Д-09): в фиче есть пометка, что очередь оплаты не
  меняется;
- пустая строка и строка из пробелов остаются строками, в том числе
  `relation_type=""` не становится `RELATION_TYPE_REQUIRED`;
- размер файла (`OptionalField.longInteger`) и список печатных форм
  (`JsonFields.hasArray`) уже отвергают чужой тип; целое в диапазоне `long`
  остаётся размером;
- при статусе ERROR у `LmPolicyIssued` номер полиса не читается, даже если узел
  не строка;
- бизнес-ошибки участника (`PROGRAM_REQUIRED`, `RELATION_TYPE_REQUIRED`)
  остаются обработанным сообщением, путь в ответе без префикса `data.`;
- возврат отклонённой строки inbox в разбор тело не чинит: нужен новый
  `message_id`;
- существующие step-классы стенда и замороженные чужие `.feature` не правились.

Сверх текста промпта всплыло по коду и по ревью, не из формулировки задачи:

- старый `OptionalField` делал `isText() ? field.text() : null`, то есть число,
  `false`, массив и объект становились пустым значением;
- `JdbcClient` `.single()` не принимает SQL NULL, поэтому сценарии «поля нет»
  сначала падали в новом step, а не в продуктовом коде;
- Jackson 3: `JsonMapper` не имеет `objectNode()` / `arrayNode()` так, как это
  было написано в первом варианте тестов;
- `longInteger` нельзя описывать той же фразой, что текст, GUID и дату
  (находка ревьюера);
- смена любого acceptance-glue на Gauntlet 4.5 мутирует все 47 фич, а не новую.
